# School Office OS 구현·검증 기록

작성일: 2026-10-27 (한국시간). 대상: `kwonyoung1/school--`. Pocket Friends 저장소·DB에는 접근하거나 변경하지 않았습니다.

## 구현 구조

- 기존 `src/main.tsx`, Express API, SQLite/Turso 저장·인증·첨부·백업·엑셀 코드를 보존하고 통합 메뉴를 추가했습니다.
- `src/office.tsx`: 시설·물품·사업·업체 지급·기한·일별 활동·보고서·검색·백업 화면.
- `shared/office.ts`: 입력 검증, 금액 합계, 취소 제외, 카드 경고, 문구 생성·추천, 한국시간·보고서 규칙.
- `shared/office-store.ts`: 공통 SQL 저장 계층. 업무 변경과 활동 이력을 한 트랜잭션/D1 batch에 저장하며 버전 조건으로 동시 수정을 방지합니다. 백업은 단일 SQL 스냅샷 조회이며, 복원은 전체 자료 변경 버전을 재확인한 원자적 작업입니다.
- `server/office.ts`: 기존 인증·권한을 재사용하는 로컬/Turso API. 기존 품의 감사 이력도 앞으로의 변경부터 오늘 한 일에 반영합니다.
- `worker/index.ts`: 표준 Request/Response 기반 Workers API. D1 바인딩 **DB**, 정적 파일 바인딩 **ASSETS**. Express의 파일시스템과 장기 프로세스에 의존하지 않습니다.
- `migrations/0001_office.sql`: 기존 테이블을 제거하지 않는 추가 스키마. 사업과 지급, 구입과 품목에 외래키를 적용했습니다. 업체는 중복 이름을 피하고 여러 지급 건이 같은 업체 ID를 참조합니다. 편집용 검증 JSON 집계와 관계형 조회 테이블을 함께 저장합니다.
- `src/cloud-main.tsx`, `vite.cloud.config.ts`: Workers 통합 화면 빌드. 기존 화면은 별도 기존 빌드로 남습니다.
- 아이콘은 Lucide를 사용합니다. 기존 CSS·폼을 보존해 두 실행 경로를 지원하며 Tailwind/shadcn 전면 재작성은 하지 않았습니다.

프런트엔드의 문구 생성과 Excel 생성은 외부 AI/API로 자료를 보내지 않습니다. 입력 후 **저장**을 누르면 서버에 기록하고 입력 중 초안은 해당 브라우저에 자동 저장합니다.

## 검증 방법

```bash
npm run build
npm test
npm run test:browser
npm run build:cloud
XDG_CONFIG_HOME=/workspace/.config WRANGLER_SEND_METRICS=false npm run check:worker
npm run test:cloud
```

`build` 완료 전 서버/브라우저 테스트를 실행하지 않습니다. `test:cloud`는 직전 `check:worker`에서 만든 번들을 실제 workerd/Miniflare+D1에서 실행합니다. 가상 자료·무작위 비밀번호·임시 DB만 사용합니다. `miniflare` 버전은 lockfile에 고정되며 현재 설치 버전은 새 옵션과 구형 옵션 변환 함수를 함께 사용합니다.

Workers 테스트는 새 runtime을 생성해 같은 D1 디스크의 계정·세션·자료가 유지되는 것을 확인했습니다. Chromium에서 다중 업체/동일 업체/혼합 결제 입력, 초과 경고, 결의와 지급 분리, 입력 초안 복구·새로고침 유지, Excel 실제 워크시트 열/행, 보고서 PDF 생성과 390px 화면 가로 넘침 없음을 확인했습니다. 기존 백업 변환은 원본 파일을 변경하지 않고 이미 존재하는 출력 파일도 덮어쓰지 않는지 검사했습니다.

빌드에는 기존 Zod 주석 처리와 큰 ExcelJS 브라우저 청크 경고가 있습니다. ExcelJS는 내보내기 때 동적 로딩하며 Worker 번들에는 들어가지 않습니다. Wrangler는 이 환경에서 외부 `Request.cf` 메타데이터 조회를 실패해 기본값을 사용했지만 로컬 API 검증은 통과했습니다.

실제 Cloudflare 네트워크 배포, 무료 계정의 CPU 제한, 학교/집/휴대폰의 실기기 접속은 아직 검증하지 않았습니다.

## 전환 및 운영 제한

1. **실제 GitHub 업로드·Cloudflare 배포는 미실행**입니다. 사용자 계정의 D1 생성·DB ID 반영·런타임 관리자 Secret·배포가 필요합니다.
2. 기존 Express의 첨부, 증빙 체크, 세부 재원 배분, 기존 달력/통계/권한/Excel 가져오기는 **기존 실행 경로에 유지**했습니다. 새 Workers UI로 동일 기능 전체를 옮긴 것은 아닙니다. 기존 사이트 폐기·전체 전환은 아직 권하지 않습니다.
3. 기존 품의 가져오기는 원본을 유지하는 1회 복사입니다. 이후 두 화면을 자동으로 동기화하지 않습니다. 새 통합사업 수정은 원본 품의를 변경하지 않습니다. CLI 변환도 원본을 변경하지 않고 새 파일만 만듭니다.
4. 백업/복원은 소규모 업무를 대상으로 합니다. 앱 복원 파일 10MB, 현재 자료의 복원 전 스냅샷 1.8MB, 분류별 복원 바인딩 1.8MB, 업무 하나 700KB 수준으로 제한합니다. D1의 행/바인딩/메모리 한도를 피하기 위한 자원 제한이며 업체 수에 별도의 개수 제한을 둔 것은 아닙니다. 큰 자료에는 D1 관리 도구 및 분할/스트리밍 개선이 필요합니다.
5. 현재 목록과 이력은 전체를 조회합니다. 소규모 개인 업무에 적합하며 자료 증가 시 페이지 조회·색인 최적화가 필요합니다. 매번 지급 집계를 재구성하므로 큰 사업은 쓰기 한도를 더 사용합니다.
6. 입력 초안은 해당 기기의 브라우저 저장소에 있고 기기 간 동기화되지 않습니다. 서버 저장 자료는 같은 배포 주소의 D1 DB를 공유합니다. 공용 PC에서 초안을 남기지 마세요.
7. Worker는 HTTPS 쿠키를 기본 사용합니다. `LOCAL_DEV=true`는 로컬 개발 전용으로 실제 Cloudflare에 설정하지 않습니다. 초기 Secret 변경은 기존 비밀번호를 덮어쓰지 않습니다. Workers의 클릭식 관리자 복구는 별도 구현되지 않았습니다.
8. D1 무료 500MB/DB, 읽기 500만·쓰기 10만 행/일, Workers 동적 요청 10만/일·CPU 10ms/요청을 확인했습니다. 로그인 해시·대규모 복원 등의 실제 무료 계정 CPU 사용량은 배포 후 검증해야 하며 무료 운영을 무조건 보장할 수 없습니다. 자동 유료 전환 코드는 없습니다.
9. 최신 약관 전문은 현재 네트워크에서 접근할 수 없었습니다. 학교 업무에 대한 법적 적합성·내부 승인을 완료한 것으로 간주하지 않습니다. 배포 안내의 공식 약관 링크·학교 규정 점검을 완료한 후 가상 자료로 시험하세요.
10. 삭제 이력·복원 스냅샷을 보관합니다. 개인정보의 물리적 영구 파기 기능은 아니므로 보관정책에 맞는 별도 관리가 필요합니다.

개발 도중 발견한 D1 compound SELECT 제한은 공통 백업 SQL을 변경해 대응했습니다. 메뉴가 늘어나 기존 화면 하단 메뉴를 누를 수 없었던 문제는 사이드바 스크롤로 수정했습니다. 테스트를 제거하거나 강제로 클릭하여 우회하지 않았습니다.
