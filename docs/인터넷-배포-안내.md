# 설치·터미널 없이 무료 인터넷 테스트 사이트 만들기

**Render 무료 웹 서버 + Turso 무료 데이터베이스**를 사용합니다. 무료 서버의 임시 디스크에 SQLite를 두지 않습니다. 계정·품의·설정·변경 이력과 첨부파일까지 Turso에 저장하므로 웹 서버가 꺼지거나 새로 배포되어도 DB 연결을 그대로 유지하면 자료가 보존됩니다. 기존 PC용 SQLite 실행 방식은 그대로 남아 있습니다.

이 구성의 `render.yaml`은 **Free** 플랜이며 유료 디스크가 없습니다. 실제 가입 화면에서 반드시 무료 요금제를 확인하고, 유료 업그레이드·결제 버튼은 누르지 마세요. 무료 요금제의 제공 여부·한도·정책은 서비스에서 변경할 수 있습니다. 현재 화면에서 무료 플랜이 없거나 결제를 요구하면 진행을 멈추고 알려주세요.

## 1. 먼저 Turso 무료 데이터베이스 생성

1. 브라우저에서 <https://turso.tech/>을 열고 **Sign Up / Get Started**를 누릅니다. Turso 콘솔은 <https://app.turso.tech/>입니다.
2. **Continue with GitHub / Sign in with GitHub**를 선택하고 GitHub 로그인·연결 승인을 완료합니다.
3. 요금제 선택 화면이 나오면 **Free / 무료**를 선택합니다. 유료 플랜은 선택하지 않습니다.
4. 콘솔에서 **Create Database / New Database**를 누릅니다.
5. 이름은 `school-expense-test`로 입력하고, 지역을 선택해야 하면 Singapore 등 서비스가 제공하는 가까운 지역을 선택한 뒤 **Create**를 누릅니다.
6. 생성한 DB를 클릭하고 **Database URL / URL**을 복사합니다. `libsql://...turso.io` 형태의 값이며 다음 단계의 `TURSO_DATABASE_URL` 칸에 사용합니다.
7. 같은 DB의 **Tokens / Generate Token / Create Token** 메뉴에서 **Read & Write / Full Access** 권한의 토큰을 생성합니다. 조회 전용 토큰으로는 품의를 등록할 수 없습니다. 만료 기간을 선택했다면 만료 전 교체해야 합니다.
8. 토큰을 복사하여 다음 단계의 `TURSO_AUTH_TOKEN` 칸에 사용합니다. **토큰은 이 채팅이나 GitHub에 붙여 넣지 않습니다.** 브라우저에서 Render의 보안 설정으로만 전달합니다.

메뉴 이름은 화면 버전·언어에 따라 조금 다를 수 있습니다. 화면에 토큰 생성 메뉴가 없다면 보이는 메뉴 이름만 알려주세요. 토큰 값·비밀번호를 보내실 필요는 없습니다.

## 2. Render 무료 웹사이트 생성

1. <https://dashboard.render.com/>을 열고 **Get Started / Sign Up**을 누릅니다. GitHub로 가입하면 저장소 연결이 편리합니다.
2. GitHub 연결·앱 설치 승인이 표시되면 **Only select repositories**를 선택하고 `kwonyoung1/school--` 저장소만 허용한 뒤 **Install / Install & Authorize**를 누릅니다.
3. Render 대시보드에서 **New + → Blueprint**를 누릅니다. 또는 [이 저장소 배포 시작](https://render.com/deploy?repo=https://github.com/kwonyoung1/school--)으로 들어갑니다. 이 링크는 배포 설정 화면이며 웹사이트 사용 주소가 아닙니다.
4. 저장소 목록에서 `kwonyoung1/school--` 옆의 **Connect**를 누릅니다. 보이지 않으면 **Configure GitHub / Configure account**에서 해당 저장소 접근 권한을 추가합니다.
5. 브랜치는 **main**, Blueprint 파일은 **render.yaml**을 선택합니다. 이름은 `school-expense-test` 등으로 입력합니다.
6. 값을 입력하는 화면에서 Turso에서 복사한 내용을 넣습니다.
   - **TURSO_DATABASE_URL:** DB URL
   - **TURSO_AUTH_TOKEN:** 읽기·쓰기 DB 토큰
7. 구성 미리보기에서 웹 서비스가 **Free**, 디스크가 **없음**인지 확인합니다. `ADMIN_PASSWORD`는 자동 생성됩니다. `SECURE_COOKIE=true`와 원격 DB 필수 설정도 포함되어 있습니다.
8. 무료 구성이 맞으면 **Deploy Blueprint / Apply**를 누릅니다. 유료 플랜이나 요금이 표시되면 누르지 말고 멈추세요.
9. 서비스가 **Live** 상태가 될 때까지 기다립니다. 설치·빌드·DB 준비가 자동 실행되며 가상 예시 2건도 생성됩니다.

서비스를 만드는 것은 가입·계정 연결 후 사용자가 직접 해야 합니다. 계정 연결 없이 이 저장소만으로 이미 운영 중인 URL을 만들 수는 없습니다. 이 준비 작업에서는 외부 계정을 만들거나 결제를 진행하지 않았습니다.

## 3. 실제 인터넷 주소와 로그인

1. Render에서 `school-expense-manager` 서비스를 클릭합니다.
2. 화면 상단의 **https://…onrender.com** 주소를 클릭합니다. 이것이 실제 웹사이트 주소입니다. Render가 생성한 주소를 사용하며 문서의 예시 주소를 입력하지 않습니다.
3. 같은 서비스의 **Environment** 메뉴에서 `ADMIN_PASSWORD` 행의 **Reveal / 눈 모양**으로 자동 생성된 초기 비밀번호를 확인·복사합니다.
4. 사이트에서 아이디 **admin**, 위에서 확인한 비밀번호로 로그인합니다.
5. **설정·사용자 → 내 비밀번호 변경**에서 본인만 아는 12자 이상 비밀번호로 바꿉니다.
6. 필요하면 사용자 관리에서 별도의 담당자·조회자 계정을 만듭니다.

웹사이트에서 비밀번호를 바꾼 뒤에는 Environment의 초기 `ADMIN_PASSWORD`와 다를 수 있습니다. 환경 변수 수정만으로 기존 계정 비밀번호가 바뀌지는 않습니다. DB를 삭제하여 초기화하지 마세요.

## 4. 기존 Codex 자료를 그대로 옮기기

GitHub에는 기존 SQLite DB·첨부파일·비밀번호를 올리지 않습니다. Codex 작업공간의 기존 자료는 그대로 유지하며, 새 호스팅 DB에는 먼저 가상 예시가 만들어집니다.

원래 자료를 옮기려면 제공된 **기존 업무 백업 JSON**을 PC에 다운로드한 뒤 새 사이트에서 **설정·사용자 → 백업 복원**을 누르고 해당 파일을 선택합니다. 품의·설정·첨부를 교체하고 기존 관리번호를 보존합니다. 사용자 계정과 비밀번호는 복원 대상이 아니므로 로그인에는 새 사이트의 계정을 사용하세요.

## 5. 보존·백업과 무료 한도

- **재시작·재배포:** DB 주소·토큰을 그대로 유지하면 자료를 다시 읽습니다. 웹 서버의 임시 디스크를 삭제해도 품의·계정·첨부는 외부 DB에 남습니다.
- **삭제 금지:** Turso DB·계정 삭제, DB 주소 변경은 기존 자료와의 연결을 끊습니다. DB를 삭제하면 복구를 보장할 수 없습니다.
- **백업:** 설정에서 **백업 다운로드**로 PC에도 보관합니다. 웹 서버 실행 시 하루 한 번 업무 복구 스냅샷을 DB에 저장하며, 복원 전에도 생성합니다. 최신 7개만 보관합니다. 자동 복구 백업 목록에서 해당 시점의 JSON을 다운로드할 수 있습니다. 이 업무 스냅샷에는 사용자 계정은 포함하지 않습니다.
- **무료 서버 대기:** Render 무료 서버는 비활성 시 중지될 수 있으며 첫 접속에 시간이 걸릴 수 있습니다. 항상 켜진 유료 서버처럼 즉시 응답한다고 보장하지 않습니다.
- **무료 DB 한도:** DB 저장량·읽기·쓰기 한도에 첨부파일과 변경 이력·백업도 포함됩니다. 작은 가상 자료로 테스트하세요. 한도가 소진되면 요청이 실패할 수 있습니다. 유료 전환 없이 사용량을 줄이거나 무료 한도 갱신을 기다려야 합니다.
- **첨부:** 개별 최대 10MB지만 무료 테스트에서는 작은 파일을 권장합니다. 내부적으로 분할하여 DB에 저장합니다. 백업에서 참조하는 삭제된 파일은 복구를 위해 일정 기간 남을 수 있습니다.
- **서비스 정책:** 무료 가입 가능 여부, 용량, 중지·토큰 만료·휴면 정책은 각 서비스의 대시보드에서 확인하세요. 이 구성은 실제 학교 자료를 위한 상시 운영·재해 복구를 보장하지 않습니다.

무료 DB 장애·삭제에도 대비하려면 반드시 DB 외부에 백업을 다운로드해 두세요. 테스트 사이트에는 실제 개인정보·금융정보를 입력하지 않습니다.

## 6. 배포 완료 후 확인

1. 인터넷 주소로 로그인하고 품의 2건이 보이는지 확인합니다.
2. 테스트 품의를 하나 등록하고 새로고침합니다.
3. 작은 증빙파일을 첨부하고 다운로드해 봅니다.
4. 백업 JSON을 다운로드합니다.
5. Render의 **Restart service** 후 다시 로그인했을 때 등록한 품의·첨부가 남아 있는지 확인합니다.

코드 업데이트 후에는 **Manual Deploy → Deploy latest commit**을 누릅니다. 자동 배포는 꺼져 있어 코드 수정이 즉시 운영 사이트를 바꾸지 않습니다. 계정과 토큰 설정을 유지하고 DB는 새로 만들지 않습니다.

생성된 사이트 URL을 채팅으로 알려주면 공개 로그인 화면과 상태 확인을 점검할 수 있습니다. 비밀번호·토큰은 보내지 마세요.
