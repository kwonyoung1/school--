# School Office OS — 처음 사용하는 분을 위한 Cloudflare 배포 안내

이 문서는 **현재 학교 업무 저장소 `kwonyoung1/school--`**에 추가한 통합 업무 화면을 배포하는 안내입니다. Pocket Friends 저장소·DB·환경변수에는 접근하거나 변경하지 않습니다. 새 저장소를 만들 필요는 없습니다.

현재 코드는 개발 환경에 작성되어 있습니다. **GitHub 업로드와 실제 Cloudflare 배포는 아직 실행하지 않았습니다.** 이 문서의 확인란을 하나씩 확인하세요. Cloudflare 화면을 직접 로그인해 확인한 것은 아니며, 아래 영문 메뉴는 공식 문서에 있는 이름을 기준으로 작성했습니다. 화면에 해당 메뉴가 없으면 임의의 비슷한 삭제·업그레이드 버튼을 누르지 말고 연결된 공식 문서와 비교하세요.

## 0. 비용과 학교 자료 사용 전 확인

이 시스템은 React/TypeScript 화면, Cloudflare Workers 서버, D1 DB를 사용합니다. Supabase·유료 AI·문자·이메일 API·R2·유료 도메인·유료 플랜을 요구하지 않습니다. `workers.dev` 기본 HTTPS 주소를 사용합니다. 신용카드나 유료 구독을 요구하는 화면이면 중단하고 **Workers Free** 선택 상태를 확인하세요.

2026-10-27에 Cloudflare 공식 문서의 공식 GitHub 원문을 확인했습니다. 운영 전 링크에서 변경 여부를 확인하세요.

| 항목                      | 무료 한도      | 영향                                                                  |
| ------------------------- | -------------- | --------------------------------------------------------------------- |
| Workers 동적 요청         | 100,000회/일   | 초과하면 오류가 발생할 수 있음                                        |
| Workers CPU               | 요청당 10ms    | 대량 JSON·비밀번호 검증·대규모 복원은 실서비스에서 CPU 지표 점검 필요 |
| Workers 메모리            | 128MB          | 대규모 자료 전체 조회·변환에는 적합하지 않음                          |
| D1 읽기                   | 5,000,000행/일 | 조회 조건·색인·데이터 크기에 따라 소모                                |
| D1 쓰기                   | 100,000행/일   | 변경 이력·색인·지급 건 갱신도 포함                                    |
| D1 한 DB 크기             | 500MB          | 현재 앱용 DB 하나의 상한                                              |
| D1 계정 전체 저장         | 5GB            | 같은 계정의 다른 DB 사용량 포함                                       |
| D1 시간 복구(Time Travel) | 최근 7일       | 별도 PC 백업도 필요                                                   |
| D1 요청당 쿼리            | Free 50회      | 앱은 여러 지급 건을 묶어 저장                                         |

무료 한도를 넘으면 요청이나 저장이 실패할 수 있습니다. 코드에서 유료 플랜으로 자동 전환하지 않습니다. 사용량이 부족하면 다음 날까지 기다리거나, 안전하게 백업·자료 정리·학교가 허용한 내부 서버 사용을 검토하세요. 백업 없이 오래된 자료를 지우지 마세요.

**무료 서비스가 학교의 공식 기록 보관 시스템으로 승인되었다는 뜻은 아닙니다.** 아래 사항을 학교 담당자와 먼저 확인하세요.

- 외부 클라우드·국외 처리/이전·위탁에 대한 학교 내부 규정과 승인 절차
- 업무 데이터에 개인정보·계좌번호·주민번호·학생 정보가 포함되는지와 최소 수집 원칙
- 접근 가능한 관리자, 관리자 PC 보안, 보관 기간, 외부 백업 위치
- 서비스 장애 때 대체 업무 절차, 복구 책임, 기록 보존 의무
- [Cloudflare 이용약관](https://www.cloudflare.com/terms/), [DPA](https://www.cloudflare.com/cloudflare-customer-dpa/), 적용되는 서비스별 약관

이 환경에서는 약관 웹페이지가 네트워크 정책으로 차단되어 **최신 약관 전문과 학교 업무에 대한 법적 적합성을 검토 완료하지 못했습니다.** 공식 D1 무료 안내는 무료 플랜을 시제품·실험 용도로 설명합니다. 무료 제공과 학교의 실제 업무 운영 허용·보장·SLA는 별개입니다. 승인 전에는 가상 자료로만 시험하세요. 외부 클라우드를 허용하지 않으면 기존 로컬 SQLite 실행을 학교가 허용하는 내부 PC/서버에서 사용하는 대안이 있습니다. 여러 장소에서의 접속은 학교가 승인한 네트워크 접근 수단이 별도로 필요합니다.

공식 근거:

- [Workers 한도](https://developers.cloudflare.com/workers/platform/limits/)
- [D1 한도](https://developers.cloudflare.com/d1/platform/limits/)
- [D1 비용](https://developers.cloudflare.com/d1/platform/pricing/)
- [D1 무료 한도 초과 안내 원문](https://github.com/cloudflare/cloudflare-docs/blob/production/src/content/partials/d1/faq-pricing.mdx)

## 1. GitHub에서 학교 저장소와 코드 확인

1. GitHub에 로그인하고 `kwonyoung1/school--` 저장소를 엽니다. 주소 끝이 **school--**인지 확인합니다. Pocket Friends 저장소는 열지 않습니다.
2. 파일 목록에 `README.md`, `package.json`, `server`, `src`가 있고 학교 지출업무 설명이 있는지 확인합니다.
3. 이 작업의 변경 내용을 Codex에서 확인합니다. `worker/index.ts`, `wrangler.jsonc`, `migrations/0001_office.sql`, 이 매뉴얼이 포함되어야 합니다.
4. 사용하는 Codex 화면에서 학교 저장소로 변경 내용을 저장하는 기능을 이용합니다. **Codex의 실제 화면은 확인하지 못했으므로 버튼 이름을 단정하지 않습니다.** GitHub에 반영되지 않았다면 Cloudflare는 새 코드를 가져오지 못합니다. 필요하면 코드 저장/PR 반영을 담당자에게 요청하세요.
5. GitHub 저장소의 `Code` 탭에서 배포할 브랜치를 선택하고 위 파일들이 보이는지 확인합니다. PR을 사용했다면 학교 저장소의 해당 PR을 검토하여 반영합니다.

정상 확인: `wrangler.jsonc` 파일이 GitHub에 표시되고 Worker 이름이 `school-office-os`입니다. 오류 시: 잘못된 저장소나 브랜치인지 확인합니다. `.dev.vars`, `.env`, `data/`, 비밀번호 파일은 업로드하지 않습니다.

## 2. Cloudflare 무료 계정

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에 접속합니다.
2. 계정이 없으면 가입 화면의 이메일·비밀번호 입력과 이메일 인증을 완료합니다. 실제 가입 화면을 확인하지 못했으므로 화면의 안내를 따릅니다.
3. 로그인 후 사용할 계정을 선택합니다. Workers를 이용할 수 있는 계정 대시보드인지 확인합니다.
4. **Workers Free**로 진행합니다. 사이트 도메인 구매나 유료 Workers 업그레이드를 선택하지 않습니다.

정상 확인: 대시보드에서 Workers 및 D1 관련 메뉴를 찾을 수 있습니다. 오류 시: 이메일 인증과 올바른 계정 선택을 확인합니다.

## 3. D1 데이터베이스 만들기

공식 문서: [D1 시작하기](https://developers.cloudflare.com/d1/get-started/).

1. 대시보드에서 **D1 SQL database** 페이지를 찾습니다. 메뉴 구조가 다르면 공식 문서의 대시보드 링크를 이용합니다.
2. **Create Database**를 선택합니다.
3. 이름에 `school-office-os-db`를 입력합니다. Pocket Friends DB와 다른 새 이름입니다.
4. **Create**를 선택합니다. 기존 DB를 삭제하거나 이름을 바꾸지 않습니다.
5. 새 DB의 식별 번호인 **Database ID**를 확인하여 복사합니다. 이 값은 비밀번호가 아닙니다. 화면 위치가 달라 찾을 수 없다면 DB 상세 화면과 공식 문서를 확인합니다.
6. GitHub의 학교 저장소에서 `wrangler.jsonc`를 열어 편집 기능을 이용합니다. `database_id`의 `00000000-0000-0000-0000-000000000000`만 복사한 ID로 바꿉니다. `binding`은 **DB**, `database_name`은 **school-office-os-db**로 유지합니다. 변경 내용을 학교 저장소의 배포 브랜치에 저장합니다.

정상 확인: DB 목록에 학교용 새 DB가 있고 GitHub 설정 파일에 실제 ID가 있습니다. 오류 시: 계정이 맞는지, 이름·ID가 다른 프로젝트의 것이 아닌지 확인합니다.

## 4. 테이블 생성: 데이터 저장 칸 준비

가장 재현하기 쉬운 방법은 배포 명령에 마이그레이션(테이블 준비)을 포함하는 것입니다. 다음 단계에서 **Deploy command**를 아래와 같이 설정하면 배포 전에 적용됩니다.

```text
npm run db:migrate:remote && npm run deploy:cloud
```

이는 학교용 DB에 새 테이블을 **추가**하며 기존 테이블을 삭제하지 않습니다. 이미 적용한 마이그레이션은 다시 적용하지 않습니다. Cloudflare가 자동 생성한 배포 토큰에 D1 권한이 없다면 배포 로그에 권한 오류가 나타날 수 있습니다. 그 경우 학교용 DB에 한정한 D1 권한을 가진 토큰 설정을 담당자와 확인합니다. 토큰을 채팅이나 GitHub 파일에 넣지 마세요.

대시보드 SQL 실행 화면을 사용할 수도 있습니다. 공식 문서에서 DB의 **Console** 탭을 안내합니다. GitHub의 `migrations/0001_office.sql` 내용을 복사하여 새 학교용 DB에서 실행합니다. SQL 실행 버튼의 현재 명칭은 화면에서 확인하세요. 다른 DB에서는 실행하지 마세요. 대시보드로 먼저 적용하더라도 이 파일의 생성 구문은 재실행 가능하게 작성되어 있습니다.

정상 확인: DB에서 `facility_tasks`, `facility_purchases`, `facility_purchase_items`, `expense_projects`, `expense_vendors`, `expense_payments`, `activity_logs`, `item_purpose_templates`, `daily_reports`, `user_settings`, 인증·복구용 보조 테이블이 보입니다. 다음 조회도 사용할 수 있습니다.

```sql
SELECT name FROM sqlite_master WHERE type='table' ORDER BY name;
```

오류 시: DB 연결 이름이 **DB**인지, 학교용 DB ID가 맞는지, `migrations` 폴더가 GitHub에 있는지 확인합니다.

## 5. GitHub를 연결하고 배포

공식 문서: [대시보드 시작](https://developers.cloudflare.com/workers/get-started/dashboard/), [빌드 설정](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/).

1. Cloudflare의 **Workers & Pages** 페이지로 이동합니다.
2. **Create application**을 선택하고 기존 Git 저장소를 가져오는 기능을 선택합니다. 공식 문서에는 기존 Git 저장소 가져오기가 안내되어 있으나 세부 버튼 문구는 현재 화면에서 확인해야 합니다.
3. GitHub 연결 화면에서 **학교 저장소에만** 접근하도록 허용하고 `kwonyoung1/school--`를 선택합니다. Pocket Friends에 대한 권한은 필요하지 않습니다.
4. 배포 브랜치에 새 코드가 반영된 브랜치(보통 `main`)를 선택합니다.
5. 프로젝트 루트는 저장소 루트로 설정합니다. `package.json`과 `wrangler.jsonc`가 있는 위치입니다.
6. 다음 빌드·배포 명령을 입력합니다.

| 설정           | 입력                                                |
| -------------- | --------------------------------------------------- |
| Worker 이름    | `school-office-os`                                  |
| Build command  | `npm ci --include=dev && npm run build:cloud`       |
| Deploy command | `npm run db:migrate:remote && npm run deploy:cloud` |
| Node 버전      | 빌드 환경에서 `NODE_VERSION=24.19.0` 사용           |

7. **Deploy**를 선택합니다. 빌드 로그에 TypeScript 검사와 Vite 빌드가 성공하고, D1 테이블 준비 및 Worker 업로드가 완료되는지 확인합니다.
8. 필요하면 해당 Worker의 **Settings > Build**에서 설정을 다시 확인합니다. 이전 빌드를 단순 재시도하면 바꾼 설정이 반영되지 않을 수 있으므로 새 빌드를 실행합니다.
9. D1 연결은 설정 파일의 `DB` 바인딩으로 배포됩니다. Worker의 연결 목록에서 학교용 DB가 연결되어 있는지 확인합니다. 대시보드에서 수동 연결할 경우에도 변수 이름은 **DB**입니다.
10. Cloudflare가 표시하는 실제 `workers.dev` 주소로 접속합니다. 주소는 계정마다 다르므로 이 문서에서 임의로 만들지 않습니다.

정상 확인: School Office OS 로그인 화면이 보입니다. 로그인 전 업무 자료는 보이지 않아야 합니다. `/api/health` 경로는 DB 상태만 확인하며 정상일 때 `status: ok`를 반환합니다. 오류 시: 7절과 아래 문제 해결 표를 확인합니다.

미리보기 브랜치를 켜는 경우 운영 DB를 그대로 연결하지 마세요. 별도 시험용 DB를 만들거나 미리보기 배포를 끕니다. 같은 운영 DB를 여러 코드 버전이 수정하면 자료가 바뀔 수 있습니다.

## 6. 최초 관리자 비밀번호 등록

공식 문서: [Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).

1. **Workers & Pages**에서 `school-office-os`를 선택하고 **Settings**를 엽니다.
2. **Variables and Secrets > Add**를 선택합니다.
3. 유형 **Secret**, 이름 **ADMIN_PASSWORD**, 값에 본인만 아는 **12~200자 비밀번호**를 입력합니다. GitHub나 채팅에 적지 마세요.
4. 선택 사항으로 일반 변수 **ADMIN_USERNAME**을 지정할 수 있습니다. 생략 시 아이디는 `admin`입니다.
5. **Deploy**로 런타임에 반영합니다. 빌드용 변수만 등록하고 끝내면 로그인 서버에서 읽지 못합니다.
6. 실제 사이트에 접속해 `admin`(또는 지정한 아이디)과 입력한 비밀번호로 로그인합니다.
7. **통합 설정·백업 > 비밀번호 변경**에서 현재 비밀번호와 새 비밀번호를 입력해 변경합니다. 모든 기존 세션은 종료되므로 새 비밀번호로 다시 로그인합니다.
8. 상단 **로그아웃**을 눌러 로그인 화면으로 돌아오는지 확인합니다.

공개 회원가입은 없습니다. 관리자 계정은 최초 로그인 요청 때 런타임 Secret을 안전한 해시로 저장하여 초기화합니다. 기존 계정이 있으면 재배포나 Secret 변경으로 비밀번호를 덮어쓰지 않습니다. 따라서 비밀번호를 잊었다고 DB를 삭제하지 마세요. 현재 Cloudflare 모드에는 별도의 클릭식 비밀번호 복구 기능이 없으므로 담당자에게 계정 보존 복구 작업을 요청해야 합니다. 기존 Express/Render 복구 환경변수는 Workers에 적용되지 않습니다.

## 7. 실제 업무 사용

전체 화면별 안내는 [USER_GUIDE.md](../USER_GUIDE.md)를 참조하세요.

1. **시설 작업계획 > 작업계획 작성**: 업무명 입력 → **자동 작성** → 현장 확인 내용 수정 → **저장**. 목록에 작업명이 나타나고 새로고침 후 유지되는지 확인합니다.
2. **시설관리물품 구입 > 구입 업무 등록**: 업무명·물품명 `락스`·수량·단가 입력 → **용도 자동 생성** → 용도 검토 → **저장**. 여러 품목은 **+ 물품 추가**를 이용합니다.
3. **지출사업 관리 > 신규 사업 등록**: 사업명·예산·품의금액·품의일 입력 → **+ 결제·지급 건 추가**. 업체별로 카드/계좌이체·예정액·기한 입력 → **저장**.
4. 같은 업체라도 다른 결제라면 지급 건을 추가합니다. 사업 상세의 합계·차액과 업체별 표를 확인합니다.
5. 사업 상세에서 **품의 완료**, 지급 건별 **원인행위 완료**, **지출결의 완료**를 각각 선택하고 **저장**합니다.
6. 실제 돈이 지급되었을 때 실제 지급금액을 입력하고 **지급 완료**를 선택합니다. 카드 승인일과 정산 지급일은 별도 상세 날짜입니다. 지출결의 버튼은 지급 상태를 바꾸지 않습니다.
7. **카드결제 기한관리**에서 업체별 주의/긴급/초과 상태를 확인합니다. 완료된 지출결의와 실제 지급 모두 확인된 건 또는 취소 건은 경고를 종료합니다.
8. **오늘 한 일**에서 한국시간 날짜를 선택하고 업무 목록을 확인합니다. 보고서 내용을 수정한 후 **보고서 저장**, **전체 복사**, **인쇄 / PDF 저장**을 이용합니다. PDF는 브라우저 인쇄 창에서 PDF로 저장하는 대상을 선택합니다.
9. 학교 PC·집 PC·휴대폰에서 **같은 실제 배포 주소**에 로그인하고 같은 업무가 보이는지 확인합니다. 각 기기의 새로고침 버튼으로 최신 자료를 조회합니다.

오류 시: 화면의 오류 메시지를 확인하세요. 다른 기기 수정 충돌이면 최신 자료를 다시 읽은 뒤 재입력합니다. 저장되지 않은 초안은 해당 기기의 브라우저에만 있고 다른 기기로 동기화되지 않습니다.

## 8. 백업과 복원

1. **통합 설정·백업 > 업무 백업 다운로드**를 누릅니다. `school-office-날짜.json` 파일이 PC에 저장되는지 확인합니다.
2. 파일에는 개인정보가 포함될 수 있으므로 승인된 안전한 폴더에 보관합니다. 공개 GitHub에 올리지 않습니다.
3. 복원 전 최신 백업을 한 번 더 다운로드합니다.
4. **백업 복원**에서 `school-office-v1` 형식 파일을 선택하고 교체 확인창을 확인합니다. 현재 통합 자료를 교체하므로 다른 기기 편집을 잠시 멈춥니다.
5. 완료 후 시설·사업·업체별 지급내역을 확인합니다. 기존 변경 이력은 유지하고 백업에 포함된 이력도 중복 없이 합칩니다.
6. 잘못 복원했다면 **복원 전 스냅샷 조회** → 해당 시각 파일 다운로드 → **백업 복원**으로 다시 불러옵니다. 최근 7개 복원 전 스냅샷을 보관합니다.

앱 복원 파일은 10MB 이하여야 하며, 복원 전 현재 자료 스냅샷이 1.8MB를 초과하면 D1 단일 행 한도에 대비해 거부합니다. 이 경우 D1 SQL 내보내기/Time Travel을 이용하는 별도 관리 작업이 필요합니다. 자동 유료 전환이나 자동 데이터 삭제를 하지 않습니다. D1의 7일 Time Travel과 별도 파일 백업을 함께 사용하세요.

## 9. 기존 지출업무 자료 보존과 이동

기존 **Express + SQLite/Turso 화면은 삭제하지 않았습니다.** 기존 첨부·증빙·재원 배분·엑셀 왕복·권한·달력·통계·백업 기능도 기존 실행 경로에 남아 있습니다. 신규 Workers 화면은 통합 업무용 별도 실행 경로입니다. 기존 Express 서버를 그대로 Workers에서 실행하는 방식은 아닙니다.

- 기존 로컬 사이트의 새 메뉴 **통합 설정·백업 > 기존 지출 품의 가져오기 (원본 유지)**로 새 통합 사업을 만들 수 있습니다. 원본은 변경하지 않고 같은 원본 ID는 다시 가져오지 않습니다.
- 로컬에서 새 통합 자료를 정리한 뒤 **업무 백업 다운로드**를 받아 Workers 사이트에서 복원하면 통합 자료를 옮길 수 있습니다. 대상의 기존 통합 자료를 교체하므로 먼저 대상도 백업하세요.
- 기존 지출 백업만 있다면 개발 환경 터미널에서 아래 변환 후 새 통합 사이트에 복원할 수 있습니다. 출력 경로에는 새 파일명을 사용합니다.

```bash
npm run migrate:legacy -- /안전한/기존백업.json /안전한/새통합백업.json
```

**이 변환은 업무명·업체·금액·일부 처리 단계만 옮깁니다.** 기존 첨부·증빙 체크·상세 재원 배분·사용자·기존 감사 이력은 새 통합 모델로 옮기지 않습니다. 원본 백업과 기존 사이트를 보관하세요. 카드 승인만으로 정산 지급 완료를 추정하지 않습니다. 가져온 뒤 두 화면은 별도 자료이며 자동 양방향 동기화되지 않습니다. 기존 기능 전체를 Workers로 이전하는 추가 작업이 남아 있습니다. 기존 사이트를 폐기하는 전환은 아직 하지 마세요.

## 10. 문제 해결

| 증상                           | 확인 및 조치                                               | 정상 확인                           |
| ------------------------------ | ---------------------------------------------------------- | ----------------------------------- |
| 빌드에서 Node 오류             | Node 24 이상 설정 확인                                     | TypeScript·Vite 빌드 완료           |
| `DB` 관련 오류 / 500           | 학교용 D1 ID와 **DB** 바인딩, 마이그레이션 확인            | `/api/health`가 정상                |
| 최초 비밀번호 설정 오류        | 런타임 **Secret**에 `ADMIN_PASSWORD` 12~200자 등록 후 배포 | 관리자 로그인 성공                  |
| 로그인 429                     | 15분 뒤 재시도, 자동 재시도 프로그램 중지                  | 올바른 비밀번호로 로그인            |
| 저장 409                       | 다른 기기 편집을 멈추고 새로고침, 최신 내용에 다시 입력    | 저장 후 버전 증가                   |
| 저장 400                       | 실제금액·지급일·음수·소수·날짜·필수항목 확인               | 오류 없이 목록 반영                 |
| 기한 날짜가 이상함             | 처리기한과 지급 예정일이 다른 항목임을 확인                | 카드 건별 처리기한 표시             |
| 화면이 예전 코드               | GitHub 브랜치·배포 로그·새 배포 여부 확인                  | 통합 메뉴 표시                      |
| Cloudflare 1027 / D1 한도 초과 | 무료 사용량 확인, 백업 보관, 초기화·유료 전환 금지         | 일일 한도 초기화 후 요청 성공       |

| 자동 복사 실패                 | 브라우저의 복사 권한 확인 또는 내용 선택 후 복사           | 문구 붙여넣기 가능                  |

## 개발 환경에서 검증할 명령 (참고)

PC 설치 없이 Cloudflare Git 빌드를 이용할 수 있습니다. 개발자가 로컬에서 검사할 때는 Node 24와 Chromium이 필요합니다.

```bash
npm ci --include=dev --cache /workspace/.npm-cache
npm run init
npm run build
npm test
npm run test:browser
npm run build:cloud
npm run check:worker
npm run test:cloud
npm run init:cloud:local
npm run db:migrate:local
npm run dev:cloud
```

`/workspace/.npm-cache`는 Codex 클라우드 환경용 경로입니다. 일반 PC에서는 `--cache` 옵션을 생략하세요. Codex에서 Wrangler 설정 폴더 쓰기 문제가 나면 `XDG_CONFIG_HOME=/workspace/.config WRANGLER_SEND_METRICS=false`를 Wrangler 명령 앞에 지정합니다. `.dev.vars`는 로컬 비밀번호 파일이며 Git에서 제외됩니다. 실제 배포에는 `LOCAL_DEV`를 등록하지 마세요. 실서비스 쿠키는 기본 Secure입니다.
