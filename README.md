# 학교 지출업무 통합관리 시스템

한국디지털미디어고등학교 행정실을 위한 실행 가능한 MVP입니다. React + TypeScript 화면, Express 서버, SQLite 데이터베이스를 사용합니다. 실제 사용자 인증·권한 검사·파일 저장은 서버에서 수행하며 브라우저를 닫거나 서버를 다시 시작해도 데이터가 유지됩니다. 회계시스템과 자동 연동되는 프로그램은 아니며 업무 진행 현황을 관리합니다.

## 설치 없이 인터넷에서 테스트하기

[버튼으로 진행하는 인터넷 배포 안내](docs/인터넷-배포-안내.md)를 따라 Render에 배포할 수 있습니다. Render 무료 웹 서버와 Turso 무료 DB를 사용하는 구성입니다. 무료 서버 디스크에는 DB나 첨부를 저장하지 않습니다. GitHub의 코드를 사용하므로 PC 설치나 터미널이 필요 없습니다.

## 처음 실행하기

Node.js **24 이상**을 설치한 후 이 저장소 폴더에서 터미널을 열고 실행하세요.

```bash
npm ci
npm run init
npm run seed  # 선택: 가상 품의 2건 생성. 기존 자료가 있으면 건너뜁니다.
npm run dev
```

클라우드 환경에서 npm 캐시 쓰기 오류가 나면 `npm ci --cache /workspace/.npm-cache`를 사용하세요.

개발 화면은 브라우저 주소창에 `http://localhost:5173`을 입력해 열 수 있습니다. 서버는 `127.0.0.1:3001`에서 실행됩니다. 원격 클라우드에서는 제품이 제공하는 포트 접근 기능이 필요합니다. 개발 서버의 5173 포트를 인터넷에 직접 공개하지 마세요.

최초 관리자 아이디는 `admin`입니다. `npm run init`은 새 데이터베이스에 무작위 비밀번호를 생성하고 `data/initial-admin-password.txt`에 현재 사용자만 읽을 수 있도록 저장합니다. 해당 파일을 로컬 편집기에서 확인해 로그인하세요. 로그인 후 **설정·사용자 → 내 비밀번호 변경**에서 비밀번호를 바꾸고 초기 비밀번호 파일을 삭제하세요. 문서에 공용 비밀번호를 넣지 않았습니다.

직접 지정하려면 최초 초기화 때 `ADMIN_PASSWORD`에 12자 이상 비밀번호를 보안 환경 변수로 넣으세요. `ADMIN_USERNAME`으로 초기 관리자 아이디도 지정할 수 있습니다. 기존 계정에는 이 변수를 다시 설정해도 비밀번호가 변경되지 않습니다. 초기화와 예시 생성은 반복 실행해도 기존 데이터를 덮어쓰지 않습니다.

## 운영용 실행

```bash
npm ci
npm run init
npm run build
npm start
```

빌드된 화면과 API를 동일한 3001 포트에서 제공합니다. 학교 운영 시 HTTPS 역방향 프록시와 내부 네트워크 접근 제한을 사용하고 `SECURE_COOKIE=true`로 설정하세요. 이 옵션은 HTTPS 접속일 때만 사용합니다. 기본 HTTP 로컬 개발에서 켜면 로그인 쿠키를 사용할 수 없습니다. 화면에는 외부 폰트·분석 스크립트를 사용하지 않습니다.

| 설정                  | 기본값               | 용도                                                      |
| --------------------- | -------------------- | --------------------------------------------------------- |
| `DATA_DIR`            | 현재 폴더의 `data`   | DB·첨부·백업 위치. 운영에서는 영속 볼륨의 절대 경로 권장  |
| `PORT`                | `3001`               | API 및 운영 화면 포트                                     |
| `HOST`                | `127.0.0.1`          | 수신 주소. 내부 컨테이너 프록시가 필요하면 `0.0.0.0` 지정 |
| `ADMIN_USERNAME`      | `admin`              | 최초 관리자 아이디                                        |
| `ADMIN_PASSWORD`      | init에서 무작위 생성 | 최초 관리자 비밀번호. 서버 직접 최초 실행 시 필수         |
| `SECURE_COOKIE`       | `false`              | HTTPS 운영 시 `true`                                      |
| `CHROMIUM_EXECUTABLE` | 설치된 Chromium      | 브라우저 테스트 실행 파일 경로                            |

`npm start` 전 `npm run init`을 실행하세요. `.env` 파일은 자동으로 읽지 않습니다. 셸 또는 운영 환경의 보안 변수 설정을 사용하세요. 서버의 작업 디렉터리는 저장소 루트여야 합니다.

## 업무 사용 순서

1. **품의 등록**에서 제목, 신청자, 결재일, 접수일, 총금액과 예산과목을 입력합니다. 관리번호는 자동 생성됩니다.
2. **결제 세부** 탭에서 카드·계좌이체 항목을 여러 개 추가합니다. 결제 방식은 항목들에서 자동 판별하며 별도 중복 저장하지 않습니다.
3. 각 결제의 업체, 예정·실제 금액, 결제일, 지출결의 예정일을 기록합니다. 한 결제에 자체예산과 지원금을 나누어 배분할 수 있고 지원사업·기관·사업기간도 기록합니다.
4. 단계별 완료 여부, 처리일, 담당자, 문서번호, 그룹명과 비고를 기록합니다. 같은 문서번호·그룹명으로 여러 항목의 공동 처리를 기록할 수 있습니다. 완료 체크 시 오늘 날짜와 로그인 사용자 이름이 자동 입력됩니다.
5. 거래에 따라 증빙 항목을 추가·삭제하고 필수 여부를 조정합니다. 품의를 저장한 뒤 **증빙 첨부**에서 파일을 업로드하세요. 파일 첨부와 확보 체크는 별도이며 담당자가 내용을 확인한 뒤 체크합니다.
6. 목록의 제목을 클릭해 결제 내역을 펼칩니다. 단계 버튼으로 빠르게 수정할 수도 있습니다. 실제 금액 또는 필수 증빙이 누락된 경우 상세 화면에서 먼저 입력합니다.

모든 결제 항목이 실제 결제·지급 완료되고 관리자가 정한 필수 단계도 끝나야 품의가 최종 완료됩니다. 실제금액·예정금액·재원 배분이 맞지 않으면 경고하고 최종 완료를 막습니다. 일부 취소 등 정당한 차이가 있으면 조정 사유를 기록해 완료할 수 있지만 경고는 유지됩니다. 데이터는 단계 완료 순서를 강제로 제한하지 않습니다.

### 화면과 집계

- **대시보드:** 전체·완료·기한 경과는 품의 수, 원인행위·카드·이체·증빙·지출결의는 결제 세부 항목 수로 명확히 구분합니다.
- **오늘 처리할 업무:** 기한 경과 → 오늘 예정 → 원인행위 지연 → 결제 후 결의 지연 → 증빙 부족 → 결제 임박 순입니다. 한 품의는 한 번 표시하고 경고 사유를 모두 표시합니다. 날짜는 한국 시간 기준입니다.
- **목록:** 제목·신청자·업체·품의번호·관리번호·사업명 검색, 접수일 범위, 결제 방식·재원·진행 상태 필터, 금액·기한·접수일 정렬을 제공합니다. 혼합결제는 별도 필터이며 카드결제만 보기에는 혼합결제를 포함하지 않습니다. 카드 대기 카드는 혼합 품의의 미결제 카드 항목도 포함합니다.
- **달력:** 접수일, 품의 기한, 결제 예정일, 지출결의 예정일을 표시합니다.
- **통계:** 결제 방식별, 월별, 자체예산·지원금별, 지원사업별 집계입니다. 혼합 재원은 각 재원 안에서 품의 중복을 제외하고 전체 수·전체 품의 금액은 한 번만 계산합니다. 재원별 실제 집행액은 해당 결제의 예정 배분 비율에 따라 나누고 표시할 때 원 단위 반올림합니다. 예정금액이 0원인 결제의 실제 집행은 재원에 배분하지 못하므로 배분을 수정하세요.
- **완료 보관함:** 완료된 품의를 보관하며 같은 검색·조회 기능을 제공합니다. 삭제하지 않습니다.
- **설정:** 알림 일수, 단계 순서·필수 여부와 사용자를 관리합니다. 이메일 알림은 MVP에 포함되지 않았습니다. 현재 알림은 저장 자료로부터 계산되므로 향후 별도 이메일 전달 작업을 추가할 수 있습니다.

### 엑셀 등록·출력

전체 또는 현재 조회 자료를 `.xlsx`로 다운로드합니다. 결제 항목당 한 행이며 동일 관리번호는 한 품의입니다. 내보낸 **지출업무** 시트가 등록 양식입니다. 기본정보와 결제 금액은 일반 열, 재원·증빙·단계의 여러 항목은 JSON 열에 저장해 정보 손실 없이 왕복합니다. 처음 사용하는 경우 예시를 내보내 양식을 참고하세요.

등록은 최대 2,000행·10MB이며 내부 압축 해제 크기도 제한합니다. 수식 셀은 허용하지 않습니다. 모든 행 검증 후 한 번에 저장합니다. 동일 관리번호의 기본정보는 일치해야 합니다. 가져오기는 **항상 새 품의를 생성**하므로 기존 파일을 재등록하면 중복 품의가 생깁니다. 기존 임의 엑셀 양식을 자동으로 매핑하는 기능은 추후 개선 대상입니다.

## 무료 인터넷 배포의 저장 방식

`TURSO_DATABASE_URL`과 `TURSO_AUTH_TOKEN`을 서버 보안 환경 변수에 설정하면 원격 libSQL(SQLite 호환) DB를 사용합니다. 품의·로그인 계정·세션·설정·변경 이력과 첨부파일의 분할 데이터까지 DB에 저장합니다. 이 두 값을 설정하지 않은 기존 로컬 실행은 `data/school.sqlite` 및 `data/uploads`를 계속 사용하므로 기존 자료를 바꾸지 않습니다.

`render.yaml`은 Free 플랜이며 유료 디스크가 없습니다. 호스팅 시작 스크립트는 원격 DB 설정이 없으면 오류로 멈추므로 무료 서버의 임시 디스크에 자료가 저장되는 일을 방지합니다. 서버는 `/api/health`로 DB 연결을 점검합니다. 무료 서버의 중지·첫 접속 지연과 DB 저장량·읽기·쓰기 한도가 적용됩니다. 실제 계정 연결 후 원격 네트워크 통신 검증이 필요합니다.

원격 모드에서는 업무·설정·첨부 연결 정보의 복구 스냅샷을 같은 DB에 보관하고 첨부 데이터는 참조되는 동안 유지합니다. 자동 백업 다운로드 화면에서 업무 JSON을 받을 수 있습니다. 사용자 계정은 업무 스냅샷에 포함하지 않습니다. DB 삭제·장애에 대비해 별도 PC에 수동 백업도 보관하세요. 무료 한도에는 첨부·이력·스냅샷도 포함되므로 가상 자료로 소규모 테스트하는 용도입니다.

## 로컬 SQLite 저장 위치와 백업

```text
data/
  school.sqlite                 사용자·세션·품의·단계·설정·변경 이력
  school.sqlite-wal / -shm       SQLite 실행 중 보조 파일
  uploads/                      서버가 생성한 무작위 이름의 첨부파일
  backups/YYYY-MM-DD/            자동 전체 백업 (DB + uploads)
  initial-admin-password.txt     최초 초기화 시 생성, 변경 후 삭제 권장
```

`data`, `.env`, 빌드 결과, 의존성은 Git에서 제외됩니다. 증빙파일은 정적 웹 경로로 노출하지 않습니다. 로그인 사용자가 인증된 다운로드 API로 접근합니다. PDF·PNG·JPG만 허용하고 확장자와 파일 시그니처를 검사하며 개별 10MB로 제한합니다. 바이러스 검사나 서류 진위 확인은 별도 운영 대책이 필요합니다.

- **웹 백업:** 관리자는 설정에서 품의·설정·첨부가 포함된 JSON을 다운로드합니다. 사용자 계정·기존 변경 이력은 이 JSON에 포함하지 않습니다. 다운로드한 파일에도 개인정보가 들어가므로 안전한 장소에 보관하세요.
- **웹 복원:** 관리자만 가능하며 현재 업무 자료를 교체합니다. 복원 전 DB·첨부 전체 백업을 생성하고 기존 사용자·변경 이력은 유지합니다. 웹 복원은 25MB 이하를 권장하며 업로드 본문은 30MB로 제한합니다. 더 큰 자료는 전체 백업으로 복구하세요.
- **자동 백업:** 서버 시작 시 및 매시간 당일 백업 존재 여부를 검사해 하루 한 번 SQLite 스냅샷과 첨부를 복사합니다. 자동·복원 전 백업을 합해 최근 7개를 보관합니다. 서버가 꺼져 있으면 자동 백업은 실행되지 않습니다. 동일 디스크 백업은 디스크 장애를 막지 못하므로 운영에서 별도 저장소 복사를 예약하세요.
- **전체 복구:** 서버를 종료한 다음 현재 `data`를 다른 안전한 위치에 복사합니다. 선택한 `backups` 폴더의 `school.sqlite`와 `uploads`를 새로운 `DATA_DIR`에 복사해 실행하세요. 서로 다른 시점의 WAL·SHM 파일을 섞지 마세요. 이 백업은 사용자 계정도 복구합니다.

데이터를 임의 삭제하면 복구가 어렵습니다. 복원과 초기화 전에 항상 백업하세요. 첨부를 삭제하거나 복원하면 이전 파일이 백업에 남을 수 있으며 보관정책에 따라 관리해야 합니다.

## 인증과 권한

| 권한   | 조회·엑셀·첨부 다운로드 | 품의·첨부 등록/수정 | 설정·사용자·백업/복원 |
| ------ | ----------------------- | ------------------- | --------------------- |
| 관리자 | 가능                    | 가능                | 가능                  |
| 담당자 | 가능                    | 가능                | 불가                  |
| 조회자 | 가능                    | 불가                | 불가                  |

학교 단일 조직 사용 모델로 활성 사용자는 전체 품의와 변경 이력을 조회합니다. 부서별·재원별 접근 제한은 아직 없습니다. 민감한 금융정보를 상세 비고에 입력하지 마세요.

비밀번호는 scrypt와 개별 salt로 해시 저장합니다. 세션은 서버에서 관리하며 DB에는 세션 토큰의 해시만 저장합니다. HttpOnly·SameSite 쿠키, 변경 요청의 CSRF 토큰, 로그인 실패 횟수 제한, 입력 검증, SQL 매개변수 바인딩, 버전 기반 동시 수정 충돌 방지를 적용했습니다. 계정 비활성화·권한 변경·비밀번호 변경 시 기존 세션을 만료시킵니다. 변경 이력은 이전·이후 업무 데이터를 기록합니다. 운영 환경의 감사 로그 외부 보관·암호화, SSO·다중 인증, 파일 악성코드 검사, 취약점 점검은 별도로 준비해야 합니다.

## 검증 방법

```bash
npm run build        # TypeScript 검사 및 운영용 화면 빌드
npm test             # 업무 규칙 및 실제 서버 통합 테스트
npm run test:browser # 실제 Chromium에서 화면 업무 흐름 검사
```

브라우저가 없으면 `npx playwright install chromium`으로 설치하세요. 시스템 Chromium은 `CHROMIUM_EXECUTABLE`로 지정할 수 있습니다. 브라우저 테스트 전에 `npm run build`가 필요합니다. 테스트는 임시 데이터베이스와 무작위 테스트 비밀번호를 사용하며 실제 `data`에는 영향을 주지 않습니다.

테스트 항목에는 카드 300,000원 + 카드 200,000원 + 이체 500,000원 중 이체가 미완료일 때 전체 완료 금지, 재원 배분·금액 차이 경고, 로그인·권한·CSRF, 동시 수정 충돌, 위장 첨부 거부, 엑셀 왕복, 백업 복원, 재시작 후 영속성, 브라우저 등록·수정과 화면 이동이 포함됩니다. 예시는 전부 가상 개인정보·거래입니다.

## 향후 개선

- 학교 회계시스템 연동, 이메일 알림 발송 작업 및 사용자별 알림 읽음 상태
- 독립적인 원인행위·지출결의 문서 그룹 화면과 일괄 처리
- 기존 엑셀 열 매핑, 파일 감염 검사·미리보기, 대용량 스트리밍 백업
- DB 마이그레이션 도구, 운영 HTTPS 배포 자동화, 기관 SSO·다중 인증
- 다기관·부서별 권한, PostgreSQL 전환, 페이지 단위 조회·대규모 통계
- 조정금액의 재원별 확정 배분, 별도 감사 로그·원격 백업 보관 정책

## 예시 품의 삭제

관리자로 로그인한 뒤 **지출업무 목록 → 해당 품의의 상세 ↗ → 품의 삭제 → 확인**을 누릅니다. 예시와 일반 품의 모두 같은 방법으로 삭제할 수 있습니다. 삭제된 품의와 결제 항목은 목록·대시보드·통계·현재 자료 엑셀 및 백업에서 제외되고 연결된 첨부 다운로드도 차단됩니다. 조회자·담당자는 품의 삭제 권한이 없습니다.

실수에 대비해 삭제 전 백업을 만들고 삭제 이력과 원본 데이터를 서버에 보관하는 방식입니다. 개인정보를 물리적으로 영구 삭제하는 기능은 아닙니다. 삭제 전 업무 백업을 복원하면 복구할 수 있습니다. 복원 시 현재 업무 자료 전체가 교체되므로 먼저 현재 자료를 백업하세요. 예시를 전부 삭제한 뒤에도 서버 시작 시 자동으로 다시 생성하지 않습니다.

## 관리자 비밀번호를 잊었거나 로그인이 되지 않을 때

호스팅 계정 소유자는 Render의 보안 환경 변수로 관리자의 비밀번호만 일회성 재설정할 수 있습니다. 품의·첨부·다른 사용자 계정은 유지합니다. 공개 비밀번호 초기화 URL은 제공하지 않습니다.

1. Render에서 `Manual Deploy → Deploy latest commit`으로 복구 기능이 포함된 코드를 적용하고 Live를 확인합니다.
2. `Environment`에서 기존 `ADMIN_PASSWORD`를 확인합니다. 복구 후 이 값이 관리자의 로그인 비밀번호가 됩니다. 값을 채팅이나 로그에 공유하지 마세요.
3. `ADMIN_PASSWORD_RESET_ID` 환경 변수를 추가하고 `reset-20261014-1`처럼 이전에 사용하지 않은 요청 이름을 입력합니다. 이 요청 이름은 비밀번호가 아닙니다.
4. 저장 후 배포·재시작합니다. `Save, rebuild, and deploy`가 있으면 사용하세요. 관리자 비밀번호를 재설정하고 관리자 세션을 만료시키며 로그인 실패 잠금을 해제합니다. 다른 계정의 비밀번호는 바꾸지 않습니다.
5. 사이트에서 `admin`과 `ADMIN_PASSWORD` 값으로 로그인한 뒤 사이트 설정에서 새 비밀번호로 변경하세요. 복구 환경 변수는 삭제해도 됩니다.

처리한 복구 요청 이름은 DB에 기록하므로 같은 요청 이름으로 재시작해도 변경한 비밀번호를 다시 덮어쓰지 않습니다. 다시 복구할 때는 새로운 요청 이름을 사용해야 합니다. `ADMIN_USERNAME`을 별도로 지정했다면 해당 활성 관리자 계정만 복구합니다. 계정이 없거나 관리자 권한이 아니면 오류로 중단합니다.
